# S2.8.4 The server decides what is ticked, with candidates and a reason

**Feature:** F2.8 Matching and confidence  
**Phase:** v2  
**Depends on:** S2.8.2; S2.8.3

As a **person adding or accepting a purchase**, I want the app to tell me which matches it is sure of, which to choose between and which to ask about, the same way on every screen.

## Acceptance criteria
- Every proposal the API returns (coverage preview, document facts, new-item accept, store and brand match, return policy) carries `decision` (`auto`, `choose`, `ask`), `confidenceBand`, a plain-words `reason`, and for `choose` the top two or three `candidates` with ids.
- `auto` means the server will bind it; the client computes no threshold. Quick add and the full form apply the same rule, so they cannot diverge.
- Brand match returns a candidate list, not one silent result.
- A low-stakes tag (category) and a high-stakes bind (warranty, return policy) use different bars, set in one place.
- The old numeric fields stay for one release so the current screens keep working while S9.10.4 to S9.10.6 move over.
