# S2.2.9 Guided forwarding setup

**Feature:** F2.2 Email-in capture  
**Phase:** v2  
**Milestone:** M6  
**Depends on:** S2.2.1 (Unique inbound address per user)  

As a **user** who would rather not give out a mailbox login (S2.2.10), I want to set up forwarding once, so order emails reach WarrantyCat without me doing anything each time.

**Scope for now:** Gmail and Apple Mail guides first; any other app gets general advice. **Revoking the address is deferred.** One message carries at most 20 forwarded orders; extras are reported back, not read.

## Acceptance criteria
- A setup page shows the user's private address with a copy button, and a short guide for Gmail, Outlook, Apple Mail and Yahoo: how to forward one email, and how to make a filter or rule that forwards mail from stores (suggested sender and subject patterns, such as "order", "shipped", "receipt")
- Gmail needs the forwarding address confirmed first; the confirmation message Gmail sends to the inbound address is recognised and shown to the user with the code or link, not dropped as an unknown sender
- "Send a test": the user forwards any email and the page shows it arrived, or that the sender was not one of their verified addresses
- Forwarding only the mail the user chooses is the default advice; the page says that a forward-everything rule sends private mail to us and recommends against it
- Mail that does not look like an order is discarded after classification, not kept (S2.2.2)
- **Add to contacts.** A button downloads a contact card (.vcf) named "WarrantyCat receipts" with the user's private address. Opening it on a phone or computer adds the contact, so from then on Gmail's Forward box (or any mail app) fills the address in when the user types "stuff". Also a copy button, and a mailto link that opens a new message to the address.
- **Forward as attachment** works too: Gmail's "Forward as attachment" sends the email as an .eml file, which S2.2.2 already reads. Mention it as the fallback when a plain forward loses detail.
- The address can be revoked and replaced from the same page

## Open question: who sent it
S2.2.1 accepts only mail from the user's verified addresses. A manual forward from Gmail is sent from the user's own address, so it passes. A Gmail auto-forward rule is different: the message can keep the store's address as the sender, so a "verified sender" check would drop it. The private address is already unguessable and revocable, so the likely answer is to accept anything sent to it and rely on that secret, plus the Gmail confirmation message and the "discard what is not an order" step. Settle this before building S2.2.1 and S2.2.9, and test with a real Gmail account both ways.
