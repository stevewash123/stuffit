# S2.2.1 Unique inbound address per user

**Feature:** F2.2 Email-in capture  
**Phase:** v2  
**Milestone:** M6  
**Depends on:** S7.6.4 (Transactional and inbound email); S7.5.4 (DDL: curation and learning schema)  

As a **user**, I want to a private address I can forward receipts to.

## Acceptance criteria
- Address is unguessable and revocable
- Only mail from the user's verified emails is accepted
- Unknown senders are dropped and counted


Update (S1.3.6): the person whose address receives a receipt creates and owns the purchase and its items.

## Status (2026-10-04, API uncommitted)
Built on Resend inbound, no migration:
- Address `r-{user}-{hmac}@{Email:InboundDomain}` is derived from the user id and the signing key, so it is unguessable and stored nowhere. `GET api/me/inbound-address` returns it (null until the domain is set).
- `POST api/inbound/resend` (anonymous): Svix signature checked over the raw body (`Email:ResendWebhookSecret`), `email.received` only. The raw .eml is fetched from Resend and goes through the same ingest as an uploaded .eml. Mail to an unknown address is dropped with a warning; a failure after that returns an error so Resend retries.
- Gaps: revoking one address needs a stored counter (migration). "Only from verified emails" is not enforced: a Gmail auto-forward keeps the store as the From, so the unguessable address is the check. The raw-download field name (`raw.download_url`) is from the docs and untested against live Resend. A mail forwarded by hand (Fwd:) may not parse as an order. No UI shows the address yet.
- Setup: verify a domain in Resend, add its MX record, create a webhook for `email.received` at `/api/inbound/resend`, then set `Email:InboundDomain`, `Email:ResendWebhookSecret` and `Email:ResendApiKey` in user-secrets.
