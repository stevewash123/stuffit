# S2.2.8 Connect an inbox (read-only, order mail only)

**Feature:** F2.2 Email-in capture  
**Phase:** future  
**Milestone:** M8 (not scheduled)  
**Depends on:** S2.2.5 (Pending items and their API); S2.2.2 (Extract purchase details from email); S2.2.7 (Suggest skipping receipts that do not need tracking)  

As a **user**, I want WarrantyCat to find my order emails without me forwarding each one.

## Decision
Never ask for an email password and never scrape a login. The ways in are forwarding (S2.2.1, S2.2.9), an app-password mailbox login (S2.2.10) and, here, the provider's own sign-in (OAuth) with the narrowest permission it offers.

## Acceptance criteria
- Gmail and Microsoft sign-in only, read-only scope; the user sees and approves the provider's own consent screen
- Only mail that looks like an order, shipping or receipt message is fetched (sender and subject patterns plus a provider-side search); everything else is never downloaded or stored
- Each matching message becomes a pending item (S2.2.5) like a forwarded one, with the same extraction and de-duplication
- A first connection looks back a limited time (for example 12 months) and shows how many were found before anything is added; the user can cancel
- "Disconnect" revokes the token at the provider and deletes the stored token at once; stored mail the user did not accept is deleted too
- Tokens are encrypted at rest and never logged
- Audit: when connected, last scan, how many fetched
- Not available until the provider's app review is done (Gmail read access needs a security assessment); until then the screen says "coming soon" and forwarding is the way

## Related
A mailbox login with an app password (IMAP) is its own story, S2.2.10. It is simpler and needs no provider review, but holds a stored credential.

## Open questions
- Cost and time of the Google security assessment for a restricted scope; whether it is worth it before there are users
- Whether a household member can connect an inbox that feeds the shared account (S1.3)
