# S2.2.4 De-duplicate forwarded receipts

**Feature:** F2.2 Email-in capture  
**Phase:** v2  
**Milestone:** M6  
**Depends on:** S2.2.2 (Extract purchase details from email)  

As a **system**, I want to avoid creating the same purchase twice.

## Acceptance criteria
- Dedupe on seller + order number
- Duplicate forward adds nothing and is logged

## Status
Built with S2.2.2 (2026-10-03): the dedupe key is store + order number (else a hash of the email). A second email for the same order updates the one pending item instead of adding another; the same email twice adds nothing and is reported to the user as already uploaded. The "logged" part is not done: there is no audit row for a skipped duplicate yet.
