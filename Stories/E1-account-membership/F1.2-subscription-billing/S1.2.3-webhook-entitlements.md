# S1.2.3 Stripe webhooks keep account status in step

**Feature:** F1.2 Subscription billing (Stripe)  
**Phase:** MVP  
**Milestone:** M5  
**Depends on:** S1.2.1 (Upgrade to paid via Stripe Checkout); S7.5.2 (DDL: account, user and billing schema)  

As a **system**, I want to mirror Stripe subscription state into the account reliably.

## Acceptance criteria
- Signature verified with the webhook secret before anything is processed
- Every Stripe event stored once in stripe_event (unique on Stripe event id) with raw payload, processed flag, processed_at and error; a duplicate delivery is acknowledged and skipped
- Events mapped to an account through the Stripe customer id, so invoice events are logged too (ConsignmentGenie only logged events that carried subscription metadata)
- Handles customer.subscription.created, updated, deleted; invoice.payment_succeeded, invoice.payment_failed; customer.subscription.trial_will_end (ConsignmentGenie does not handle it)
- Account caches status (trialing, active, past_due, canceled), current period end and plan features so pages never call Stripe per request
- Failures recorded and retried; endpoint returns success only after the event is safely stored

## Notes
ConsignmentGenie API: SubscriptionController webhook > StripeService.ProcessWebhookAsync > ConstructEvent, SubscriptionEvent log, cached status and period end on the organization.
