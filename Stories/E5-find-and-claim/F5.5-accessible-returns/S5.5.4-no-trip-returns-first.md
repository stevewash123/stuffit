# S5.5.4 No-trip returns first

**Feature:** F5.5 Returns that work for people with disabilities
**Phase:** future, tentative, speculative
**Milestone:** M8 or later (proposed); the per-seller method data comes from S3.2.6
**Depends on:** S3.2.6 (return method and channel); S5.4.12 (refund wizard); S5.4.6 (deadline with transit)

As a **user** for whom a store visit is hard, I want the app to show return routes that need no trip first, and to warn me early when one does, so I have time to arrange help.

## Acceptance criteria
- A setting, **Prefer returns that do not need a store visit**, on the user's preferences (not tied to any reason). It can also be set for one return in the wizard ("How would you like to return it?").
- The item page and wizard order return options by that preference: mail with a prepaid label, carrier pickup, curbside or door service, phone or chat, then in store. Each shows its cost and any limit ("mail return: label fee $7.95, taken from the refund"). The data comes from the seller policy's return method (S3.2.6) and the guidance steps (S5.4.2).
- When the only route is in store, say so at the top and show the deadline with a reminder timed earlier than usual (default 7 days before, configurable) so there is time to arrange a ride or help.
- Offer a draft message the user can send before going: "I use a mobility device. Can this return be taken at the entrance or by mail?" The user sends it; the app does not contact the store (S5.4.5).
- A seller note ("mail return free", "curbside return available", "store visit required") appears when we have it, with source and confidence (S3.2.5), including notes learned from several accessibility stories (S5.5.3) once an operator checks them.
- Nothing in the interface calls the setting a disability setting or asks why.
