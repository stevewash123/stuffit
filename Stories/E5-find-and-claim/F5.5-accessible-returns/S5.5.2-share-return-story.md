# S5.5.2 Share my return story

**Feature:** F5.5 Returns that work for people with disabilities
**Phase:** future, tentative, speculative
**Milestone:** M8 or later (proposed)
**Depends on:** S3.2.1 (parties); the mark-as-returned record (item return form); S7.2.2 (crowd data terms and consent); S5.5.3

As a **user** who returned something, I want to tell other people how it went with this store, so they know what to expect, and I want to read what happened to others before I go.

## What it is
A store page (and the policy on it) lists short return stories from users: when, how they returned it (in store, by mail, curbside), whether they got their money back and how, how hard it was, and what went wrong. It is the shared, public version of what the user already records privately when marking an item returned (date, refund, method, difficulty from 1 to 5, issues).

## Acceptance criteria
- On the "Mark as returned" form or the return card, a user can choose **Share this experience** after saving. Nothing is shared by default. The form's notes and amounts stay private; the story is a separate, editable post the user writes or accepts from a pre-filled draft.
- A story has: store (a party), the channel (online or in store, S3.2.6), the return route used, outcome (refunded, store credit, refused, still waiting), a 1-to-5 ease rating, how long it took, and free text. No names of staff, no order numbers, no card details; the post form warns and a screen strips obvious ones.
- Stories show on the store page (and brand page) with the date, the store's current policy next to them, and a note "Experiences vary; this is not the store's policy."
- Posting needs a verified email and acceptance of the crowd-content terms (S7.2.2). The author can edit or delete at any time. Authors are shown by a display name chosen for this, never the account email.
- Anyone can report a story. Reported stories go to a moderation queue (E7). Stories about a named employee, with personal data, or that read as defamation are removed.
- Stories are not evidence of policy. They never change a policy's confidence (S3.2.5) unless an operator reads one and starts a check (S6.1). They can prompt a diagnostic sweep (S6.3.1) when several say the same new thing.
- A reader sees a count and a simple summary at the top (for example "12 stories; most got a refund within a week; 4 mention long lines") built from the structured fields, not the text.

## Notes
- Open question in S5.5.1: is a forum with replies wanted, or are structured stories enough? Start with stories only. Replies and threads add moderation load.
- Legal: terms must cover user-generated content, takedowns, and a no-defamation rule. Needs the lawyer review already on the launch list.
