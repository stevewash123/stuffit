# F5.4 Return and refund guidance

**Epic:** E5 Find & Claim
**Phase:** MVP candidate (S5.4.1 to S5.4.3, S5.4.10), v2 and later for the rest

WarrantyCat already says **which** coverage to try first and when it ends (F5.1). This feature says **how**: the steps, what to bring, what to expect, and what to do next. The guidance is curated reference data, versioned and sourced like every policy fact, and the user always takes the action.

## Principles
- **Sourced, dated, versioned.** Steps are data attached to a policy version (S5.4.2), shown with source and verified date (S5.4.10). Unknown stays unknown.
- **Help, never speak for the user.** We prepare the message; the user sends it. We never contact a company on someone's behalf and never promise an outcome.
- **Start where the data is good.** The most common sellers and cards first; the long tail through user corrections and the curation queue.
- **Honest trade-offs.** Taking one route can close another; say so (S5.4.5).

## Open questions
- How much of S5.4.2 can be seeded by hand before launch? Suggest the 20 biggest retailers and the cards from S3.2.4.
- Do we deep-link into a seller's own return flow (Amazon, Best Buy) when they offer a URL that accepts an order number? Check terms of use before relying on it.
- Does the claim log (F5.2) become part of this feature, since S5.4.7 is its first real content?
- Whether to localise steps for other countries; today the data model is US-oriented.
