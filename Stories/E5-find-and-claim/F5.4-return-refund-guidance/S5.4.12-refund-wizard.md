# S5.4.12 Refund wizard: tell us what happened

**Feature:** F5.4 Return and refund guidance  
**Phase:** MVP candidate  
**Milestone:** unassigned  
**Depends on:** S5.4.1; S5.4.2; S5.4.13; S9.2.6  

As a **user**, I want to answer a few plain questions and be told which of my coverages apply and what to do.

## Acceptance criteria
- Opens from the Refund button on the item (S9.2.6) and from the Something-broke view (F5.1); route `/items/{id}/refund`
- Step 1, why: changed my mind; it does not work or broke; it arrived damaged; it is not what I ordered or expected; I found it cheaper; something else
- Step 2, the situation: only questions that change the answer (S5.4.17), for example is it in its original packaging, did it ever work, when did the problem start, do you still have the receipt, was it dropped or misused
- One question per screen on a phone, a few per screen on desktop; Back keeps answers; progress shown ("Step 2 of 3")
- Every question has "Not sure"; a not-sure answer widens the result instead of blocking it
- Step 3 is the result (S5.4.14)
- Nothing is sent to anyone; the wizard only advises. Answers are kept on the item as an attempt (S5.4.15) so the user can come back
- Uses the item's own coverages and dates; asks nothing we already know (seller, card, purchase date)
- Plain language, no jargon; works with keyboard and screen readers; Cancel returns to the item

## Status
Mock built at `/items/sample/refund` on sample data (reasons, conditions, ranked result with steps). Rules are in the page for the mock; they move to the API with S5.4.13 and S5.4.14.
