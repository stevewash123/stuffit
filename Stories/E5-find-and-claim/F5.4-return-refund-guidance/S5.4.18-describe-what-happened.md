# S5.4.18 Describe what happened (free-text intake for the wizard)

**Feature:** F5.4 Return and refund guidance  
**Phase:** future  
**Milestone:** M8  
**Depends on:** S5.4.12 (Refund wizard); S5.4.17 (Question bank); S7.6.5 (LLM integration and cost control)  

As a **user**, I want to tell the wizard what happened in my own words and have my answers filled in, so I do not have to find the right option myself.

## Acceptance criteria
- An optional "Describe what happened" box above step 1 of the wizard; the normal steps remain and work without it
- A model maps the text onto the wizard's existing fields only: the reason, and the answers from the question bank (condition, misuse, receipt, when the problem started). It returns structured values and a confidence for each; it never returns a verdict, a coverage, a deadline or steps
- The mapped answers are shown pre-filled in the normal steps so the user can see and change them before continuing; nothing is used without the user passing through them
- Anything the text does not settle is left blank and asked as usual; low-confidence values are left blank, not guessed
- Whether a coverage applies is still decided only by the sourced eligibility rules (S5.4.13, S5.4.14)
- The text is personal data: kept only with the attempt (S5.4.15), covered by export and account deletion (S1.4.1, S1.4.2), and not used to train anything or shared
- Cost is capped per account and per day (S7.6.5); over the cap the box says it is unavailable and the wizard carries on without it
- Failure or timeout never blocks the wizard
- Tested against a set of sample descriptions (for example "screen went black after a storm", "bought the wrong size", "it was a gift and I do not have the receipt") with the expected mapped answers; a wrong mapping is a defect

## Notes
Deferred until the deterministic wizard is live and there is evidence people want to type instead of tap. Related uses of a model at the edges (message drafting S5.4.4, document reading S2.7.4, unknown sellers S5.4.9) follow the same rule: the model reads and drafts, the user confirms, the sourced data decides.
