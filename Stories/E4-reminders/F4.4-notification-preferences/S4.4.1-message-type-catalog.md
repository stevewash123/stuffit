# S4.4.1 Message type catalog

**Feature:** F4.4 Notification preferences (message type x channel)  
**Phase:** MVP  
**Milestone:** M4  
**Depends on:** S7.5.2 (DDL: account, user and billing schema); S7.5.6 (DDL: notification and messaging schema)  

As a **developer**, I want to a single defined list of notification message types, grouped into categories.

## Acceptance criteria
- Catalog of categories, each with message types (key, label, description)
- Per type: default channels, default delivery mode, mandatory flag, configurable lead time or threshold, in-app action URL template and action label, email template key
- Served by the API so the preference grid, notification center and dispatcher use one list with no hardcoded copies
- Initial categories: Expiring (return window closing, warranty expiring, extended plan expiring, card benefit expiring); Purchases (purchase added by email, purchase needs info, receipt could not be read); Policies (card policy change to confirm, policy change affecting an item); Summaries (daily digest); Account (subscription reminder, payment failed, security); Product news (marketing, opt-in)
- A locked System Alerts category (payment failed, security, legal) is mandatory and non-optional
- Adding a type requires no schema change and no UI change; type keys are stable and append-only

## Notes
ConsignmentGenie keeps the type list in four places (a bit-packer index, default settings, the UI filter, the DTO). One catalog avoids that.

## Status

Done (M4, API): catalog in code at `StuffIt.Core/Notifications/NotificationCatalog.cs`, served by `GET /api/notification-types`. Per type: channels, mode, mandatory, default lead days, action template, email template key. Tests: `NotificationApiTests.cs`. The UI grid is S4.4.2.
