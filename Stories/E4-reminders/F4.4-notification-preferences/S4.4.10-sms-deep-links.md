# S4.4.10 Every SMS links to more info

**Feature:** F4.4 Notification preferences (message type x channel)  
**Phase:** v2 (ships with SMS, S4.4.4)  
**Milestone:** M8  
**Depends on:** S4.4.4 (SMS opt-in and verification); S4.5.1 (Notification record and API); S4.5.3 (Notification Center page)  

As a **user**, I want every text message to include a link to more information, so I can see the details and act from my phone.

## Acceptance criteria
- Every SMS ends with a link; the dispatcher refuses to send an SMS that has none
- The link uses our own short branded domain (carriers filter generic shorteners), https, short enough to keep the message to one segment where possible
- The link opens a mobile-first landing page for that one notification: what happened, which item, the dates that matter, and the primary action button
- The link code is random and unguessable, scoped to one notification and one user, expires (about 30 days), can be revoked, and lookups are rate-limited; unknown or expired codes return 404, not 403
- Viewing works without signing in and shows only the minimum (item name, dates, what to do); any action (confirm, edit) asks for sign-in and returns to that notification afterward
- The SMS text itself carries no sensitive detail (no card numbers, prices or account info)
- Opening the link marks the notification read and records opened_at, so we can see which channels work
- Email notifications reuse the same link format
- SMS keeps the STOP and HELP handling from S4.4.4

## Notes
Table: notification_link (code, notification_id, user_id, expires_at, opened_at). UI route: /n/:code, reachable signed out. Requirement from Steve, 2026-09-30.
The short-link domain is configuration (Sms:ShortLinkDomain), like the email sender addresses.
