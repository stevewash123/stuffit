# S4.4.8 Email compliance and one-click unsubscribe

**Feature:** F4.4 Notification preferences (message type x channel)  
**Phase:** MVP  
**Milestone:** M4  
**Depends on:** S4.4.3 (Dispatcher: store preferences and enforce them on every send); S7.6.4 (Transactional and inbound email)  

As a **user**, I want to stop emails I do not want without logging in.

## Acceptance criteria
- Every optional email has a footer with sender identity and mailing address and an unsubscribe link
- List-Unsubscribe and List-Unsubscribe-Post (one-click) headers included
- Unsubscribe token is signed (HMAC) and expires, carrying user and message type; it is not reversible user data
- Choose scope on the landing page: this type, this category, or all optional email; no login needed
- Mandatory types (payment failed, security, legal) are exempt and are never switched off by unsubscribe all
- Each unsubscribe is recorded for audit and reflected in the preference grid
- Sender address and base URL come from configuration

## Notes
ConsignmentGenie EmailComplianceService: encrypted token, 90-day expiry, scopes (specific, category, all), headers, footer. Gaps: unsubscribe all also disables mandatory types; sender and base URL hardcoded; sent-email audit only logs.

## Status

Done (M4, API): `UnsubscribeTokens` (HMAC-SHA256, 90 days, key derived from the signing key), `UnsubscribeService`, `api/unsubscribe` (GET info, POST scope type/category/allOptional, POST one-click per RFC 8058; all anonymous, bad or expired token = 404, mandatory type = 409). Optional emails get the footer link plus List-Unsubscribe and List-Unsubscribe-Post headers; mandatory emails get neither. Only email is switched off, never in-app; mandatory types are never touched. Each unsubscribe writes an `email_unsubscribe_event`. Config: `Email:MailingAddress` (footer; MUST be set before launch), `App:ApiBaseUrl`. Not yet: the UI landing page `/unsubscribe/:token` and the grid reflecting it (S4.4.2); `LoggingEmailSender` prints the headers but a real sender must send them (S7.6.4).
