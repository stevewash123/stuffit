# S4.4.7 Seed default preferences at signup

**Feature:** F4.4 Notification preferences (message type x channel)  
**Phase:** MVP  
**Milestone:** M4  
**Depends on:** S4.4.1 (Message type catalog); S1.1.1 (Sign up and log in with email)  

As a **system**, I want to every new user starts with sensible notification settings.

## Acceptance criteria
- On account creation, preference rows are created from the catalog defaults (email and in-app on, SMS off; news off)
- Existing users get rows for new catalog types through a migration or lazy fill, using the catalog default
- A missing row is never interpreted as a silent yes

## Notes
ConsignmentGenie DefaultSettingsService creates defaults at registration; its lookup still treats unknown types as enabled.

## Status

Done (M4, API): `PreferenceService.EnsureDefaultsAsync` runs at signup (inside the signup transaction): one row per optional type and channel from the catalog default; mandatory types have no rows. Rerunnable and never overwrites a choice, so it also fills rows for types added later; `--seed-preferences` does it for all existing users. A missing row still falls back to the catalog default in the dispatcher, never to yes. Tests: unit (catalog) and `PreferencesAndUnsubscribeTests`.
