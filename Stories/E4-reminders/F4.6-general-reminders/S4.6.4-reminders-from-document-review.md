# S4.6.4 Reminders found by document review

**Feature:** F4.6 General reminders (to-dos)
**Phase:** v2 (needs the document review process; not written yet)
**Milestone:** unassigned
**Depends on:** S4.6.1; S6.6.1 (contributed warranty documents); S7.6.5 (LLM integration and cost control)

As a **user** who uploads the papers that came with a purchase, I want the system to notice things I must do, such as "register your warranty within 30 days", and offer them as reminders.

## Acceptance criteria
- When a document is reviewed, anything that reads as an action (register, send a form, keep proof of purchase, claim by a date) becomes a **suggested** reminder (S4.6.1): title, a short body, the link if there is one, the due date if the document states one or can be worked out from the purchase date, the quote and page it came from, and a confidence.
- The review process writes only through the S4.6.1 API shape. It does not need a new table or a new screen for a new kind; unusual findings go in the free details field.
- A found reminder is never active until the user accepts it. Wrong ones can be marked Not applicable, and that feeds back to improve the review.
- A deadline derived from a date in the document is shown as "worked out from your purchase date" so the user can check it.
- Duplicate findings from the same document (or the same finding on a later upload) are merged, not repeated.
- The same finding on the same product from several people can raise a shared note that the product has a registration step (feeds F6.x curation); no personal data is shared.
