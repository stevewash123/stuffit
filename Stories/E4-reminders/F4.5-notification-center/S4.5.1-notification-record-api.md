# S4.5.1 Notification record and API

**Feature:** F4.5 Notification Center (in-app)  
**Phase:** MVP  
**Milestone:** M4  
**Depends on:** S7.5.6 (DDL: notification and messaging schema)  

As a **developer**, I want to store notifications and expose them through an API.

## Acceptance criteria
- Notification record: to user, from (system or a user) and type, type key, title, message, created_at, is_read, read_at, is_important, reference type and id, action_url, action_label, payload/metadata (JSON for templates and display)
- Action lifecycle: action_status (pending, completed, failed, cancelled) with completed_at and completed_by
- Acknowledgment for notifications that need an explicit I have seen this: is_acknowledged, acknowledged_at
- Delivery tracking per channel (email_sent_at, email_status, sms_sent_at, sms_status)
- Soft delete (deleted_at); dismissed notifications are hidden, not destroyed
- Endpoints: list (paged; filter by type, read state, action status, text search, date range), unread count, mark read, mark unread, mark all read, mark or unmark important, acknowledge, delete
- All filters are applied server-side
- Scoped to the signed-in user and account; no role-prefixed URLs needed
- Written by the dispatcher (S4.4.3) when the In-app channel is enabled for that type

## Notes
ConsignmentGenie Notification entity has all of these fields (FROM/TO pattern, ActionStatus, IsAcknowledged, EmailSent/SmsSent, DeletedAt, Payload and Metadata JSONB). Its list endpoint supports type, read state, attachment, from/to dates and sorting; the UI search box never reached it, so define filters here first.

## Status

Done (M4, API): `api/notifications` list (type, read, important, actionStatus, q, from, to, paging), `unread-count`, read, unread, `read-all`, `important`, `acknowledge`, soft delete; scoped to the signed-in user. The dispatcher that writes records is S4.4.3. Tests: `NotificationApiTests.cs`.

Update: hidden rows (`is_hidden`, in-app preference off) are excluded from every endpoint. System alerts can only be deleted after acknowledge (409 otherwise).
