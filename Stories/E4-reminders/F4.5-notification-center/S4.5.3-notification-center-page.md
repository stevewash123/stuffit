# S4.5.3 Notification Center page

**Feature:** F4.5 Notification Center (in-app)  
**Phase:** MVP  
**Milestone:** M4  
**Depends on:** S4.5.1 (Notification record and API); S9.1.1 (Responsive, mobile-first layout)  

As a **user**, I want to review, filter and act on all my notifications.

## Acceptance criteria
- Card list: date and time header, type icon, title, message, metadata chips (item name, seller, expiry date), unread indicator, needs-action badge for pending actions
- Per-card actions: toggle read/unread, primary action button that deep-links via action_url with the action_label (hidden when there is no action), delete
- Delete and other confirmations use the shared in-app modal, never a browser dialog
- Filters: type (from the catalog), text search, date range, unread only, needs action; filters are sent to the API
- Paged list (20 per page) with page numbers
- Empty states: all caught up (no notifications) and no matches with a Clear filters button
- Opening with ?focus=id scrolls to that card and highlights it for a couple of seconds, then clears the parameter
- ?focus works when the card is not on page 1 (the API returns the page containing the id, or the page loads it with GET /api/notifications/{id})
- A test that every key in the UI's icon and label maps exists in GET /api/notification-types
- Link to Notification Preferences (S4.4.2)
- Mark all read in the header

## Notes
Mirrors the ConsignmentGenie notification-center component. Its icons are emoji and its delete uses confirm(); we use proper icons and the shared modal.
