# S4.2.4 Consolidate bursts of events

**Feature:** F4.2 Digests and consolidated notifications  
**Phase:** v2  
**Milestone:** QA  
**Depends on:** S4.4.3 (Dispatcher: store preferences and enforce them on every send); S7.6.2 (Background job scheduler); S2.2.3 (Needs-info review queue)  

As a **user**, I want to get one message when many things arrive at once.

## Acceptance criteria
- When several events of the same type arrive close together (e.g. ten forwarded receipts), one consolidated notification is sent: 10 purchases added
- A pending-consolidation record per user and type holds the item ids, scheduled send time and job id; each new event extends the window (debounce, about 5 minutes) up to a maximum wait so it can never be delayed indefinitely
- Sending claims the row atomically (processing_started_at) so a notification is never sent twice
- Sent, failed and failure reason recorded; failed rows are retried or surfaced, not silently dropped
- Old completed rows are cleaned up after about 7 days

## Notes
ConsignmentGenie ConsolidatedNotificationService + ConsolidatedNotificationJob + PendingConsolidatedNotification (Hangfire delayed job, 5-minute debounce, claim by ProcessingStartedAt, 5-second grace delay). Its debounce has no maximum wait and the grace delay sleeps inside the job; we use a max wait and no sleeps.
