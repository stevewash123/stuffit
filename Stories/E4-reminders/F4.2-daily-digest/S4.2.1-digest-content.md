# S4.2.1 Digest content and frequency

**Feature:** F4.2 Digests and consolidated notifications  
**Phase:** v2  
**Milestone:** QA  
**Depends on:** S4.1.2 (Daily job sends due reminders); S2.2.3 (Needs-info review queue); S4.2.3 (Digest batch job)  

As a **user**, I want to a single summary, only when something changed.

## Acceptance criteria
- Each message type has a delivery mode in the preference grid (S4.4.2): Instant, Daily digest, or Weekly on a chosen day; the digest lists the types set to daily or weekly
- Content like: X purchases added, Y need info, Z expiring soon, with deep links
- No email when there is nothing to report
- Digest time of day and timezone are per user

Update 2026-10-19: Error-level items (high value, still unresolved) go in the digest with the return-window closing date, using the recipient's own minimum. The rules (colours, the two values of a line, per-person minimum, dismiss confirmation) are in S9.2.11.

## Status

2026-11-02 (feat-digest, API + UI, not merged): Done for the daily digest; weekly NOT built. Each digest-able type (return window closing, warranty expiring, extended plan expiring, info needed) has a per-person mode on the grid, At once or In my daily digest (stored in `notification_type_setting`; the grid API `PUT api/notification-preferences/{type}` takes `mode`, the GET returns `digestible` and `mode`). A type in the digest has its separate email held (notification written, in-app unchanged, `email_status` Held). The existing "Daily digest" Email box is the master switch (default on); off means nothing is held and mail arrives at once. `DailyDigestJob` emails ONE message per person at their own local reminder time (profile time zone and ReminderTime, 9:00 default) listing what is held, with deep links; nothing held, nothing sent. Held notices already done (to-do completed), older than 14 days, or whose type email was switched off since are dropped, not listed. The unsubscribe footer and List-Unsubscribe headers are on the digest email. Content is built from the held notifications (so to-dos appear when they have a nudge; an overdue to-do with no nudge is not listed), not from a fresh scan. NOT done: S9.2.11 Error-level items; a Weekly mode; per-type delivery mode UI beyond At once / Daily. Tests: `DigestComposerTests`, `NotificationEmailBuilderTests`, `DailyDigestTests` (in `ReminderSendTests`), `settings.spec.ts`.
