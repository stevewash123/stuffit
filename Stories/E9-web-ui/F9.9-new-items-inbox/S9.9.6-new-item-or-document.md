# S9.9.6 Each arrival: a new item, or a document for one I already have

**Feature:** F9.9 New Items inbox  
**Phase:** v2  
**Milestone:** M6  
**Depends on:** S9.9.1 (New Items list); S2.2.5 (Pending items and their API); S2.2.11 (Capture from the phone)  

As a **user**, I want to say whether something that arrived (a forwarded email, a scanned receipt, a shared photo) is a new purchase or just a document for something I already track.

## Why this matters
Not everything that arrives is a new purchase. A shipping notice, a warranty card or a second receipt page belongs to an item the user already has. Matching on order number or date works when those are present, but they often are not, so the user must always be able to decide, and the decision must take one tap.

## Acceptance criteria
- Every row in New Items, whatever it came from (email, upload, scan, share), has two choices: **New item** and **A document for something I already have**.
- **Default.** New item, unless there is a likely match: the same order number, or a related item (same store and a close date, or the same model or serial). Then the row opens on "A document for [item]" with the match shown and a **Not this one** button that switches to New item or lets the user pick a different item. Matching is a suggestion, never silent: nothing is attached until the user confirms.
- **Choosing an existing item** uses the same picker as the share screen (S2.2.11): search my items, most recent first, suggested matches on top, and a kind (receipt, warranty or registration paperwork, manual, other). The file, or the saved email and its attachments, becomes a document on that item, and the row leaves New Items.
- Undo is available, as for Dismiss (S9.9.4).
- **Page name.** "New Items" now holds things that are not all new items. Decide between keeping the name with a one-line explanation, or renaming the tab (for example "Inbox", or "New Items and Documents"). Count badge (S9.9.5) counts every waiting row.
- A shared file the user already placed on the share screen (S2.2.11) never lands here undecided; this story covers the arrivals that came in without that choice.

## API
`POST /api/pending-items/{id}/attach/{itemId}?type=` attaches every document of the pending item to the item and marks the pending row done, in one transaction, with an audit row. A suggested match comes with the pending item (`likelyItem`).

## Not in this story
Reading dates and order numbers well enough to match more often is S2.2.2's job; this story works without it, with the user choosing.

## Status

Built 2026-10-03 (API and UI; not browser-checked). Every New Items row has **For something I have**, which opens "Which item is this for?": the kind (receipt, warranty or registration paperwork, manual, other) and a search over my items, newest first; picking one attaches everything that came with the row and the row leaves (toast with an Open link). When there is a likely match the row says so ("Looks like a document for X. Same order number (A1).") with **Attach it there**, and the picker opens with that suggestion on top and its own button. Matching today: the same order number (strong), or the same store within a day when exactly one item fits; anything less gives no suggestion. `POST /api/pending-items/{id}/attach/{itemId}?type=` moves all the row's documents onto the item (audit "attached"; repeating for the same item is harmless; another account's item is 404; a dismissed or already-placed row is 409). Shared picker: `ItemPickerComponent`, also used by the share screen (S2.2.11). Tests: `PurchaseApiTests.AttachToItem`, `new-items.page.spec.ts`, `share.page.spec.ts`.
Not done: undo, the page rename question, matching on model or serial or item name.
