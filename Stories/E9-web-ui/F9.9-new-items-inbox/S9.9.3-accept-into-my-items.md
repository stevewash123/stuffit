# S9.9.3 Accept into My Items

**Feature:** F9.9 New Items inbox  
**Phase:** v2  
**Milestone:** M6  
**Depends on:** S9.9.1 (New Items list); S2.2.5 (Pending items and their API); S3.1.5 (Default coverage for a pending item)  

As a **user**, I want to accept a pending item in one tap when the default coverage looks right.

## Acceptance criteria
- "Accept" is enabled only when the item has at least one default coverage; otherwise it is disabled with a tooltip saying why
- Accept creates the purchase and item with the coverages shown, using the best information we have; unknown fields stay blank and can be edited later
- The item then appears in My Items and leaves New Items; a short confirmation links to it
- Reminders start from the accepted coverages (F4.1)
- Accepting twice (double tap, two tabs) is safe: one purchase
- A coverage computed from an approximate date can still be accepted; it is shown as a range marked "date estimated" (S3.1.6) and the item keeps a "confirm the date" prompt (S2.7.11)
- If the details changed since the page loaded (the coverage list differs), the user is told and nothing is accepted until they confirm

## Status
Done (2026-10-02): calls `POST /api/pending-items/{id}/accept`, removes the row, and shows "Added … to My Items" with a link to the purchase. A server refusal (409) is shown and the row stays.
