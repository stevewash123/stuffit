# S9.9.2 Add Details opens the prefilled form

**Feature:** F9.9 New Items inbox  
**Phase:** v2  
**Milestone:** M6  
**Depends on:** S9.9.1 (New Items list); S9.3.1 (Create a purchase)  

As a **user**, I want to complete a pending item in the normal purchase form with what we found already filled in.

## Acceptance criteria
- "Add Details" opens the purchase form at `/add/new` with item name, date, total, order number and price filled in
- Store and card are preselected when we matched them to a known party or card; otherwise the form names the store we read so the user can pick it
- A note on the form says what the values came from (email subject or file name)
- The source receipt or email is attached to the purchase automatically
- Saving updates the pending item (it becomes a purchase, status accepted) instead of creating a second record, then shows the proposed coverages (S9.4.2) as usual
- Cancel returns to New Items with the row unchanged
- Opening the form directly (reload, shared link) works by loading the pending item by id, not from in-memory navigation state

## Status
Done (2026-10-02): opens as `/add/new?pending=<id>`, loads the item by id (a reload keeps working), prefills store, brand, category, card, date, total and order number, and saves through `POST /api/pending-items/{id}/complete`, which marks the item done and moves its receipt onto the purchase.
