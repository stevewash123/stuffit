# S9.10.9 The item page stops leaking loads

**Feature:** F9.10 UI structure and honesty  
**Phase:** MVP  
**Depends on:** none

As a **person moving between items**, I want a slow load of one item never to show on another.

## Acceptance criteria
- The long-lived loads (item, proposals, document read) are cancelled with `switchMap` and `takeUntilDestroyed`; a route change cannot complete an older load afterwards (F3, F13).
- A spec goes from one item to another with the first answer arriving last and shows the second item.

## Notes
Do before the split in S9.10.10.

## Status
Built (Push 65). The item, plan-record and suggestion loads of the item page are cancelled when a newer load starts and when the page is left; a spec shows the second item when the first answer is cancelled. This is the unsubscribe version; the other ~45 subscriptions on the page are short HTTP calls and move out with the S9.10.10 split.
