# S9.10.8 Coverage previews cannot overwrite each other or hide a failure

**Feature:** F9.10 UI structure and honesty  
**Phase:** v2  
**Depends on:** none

As a **person adding a purchase**, I want the coverage shown to match what I last typed, and a failed lookup not to look like no coverage.

## Acceptance criteria
- The preview reload is driven by an explicit form stream with `switchMap` per row, replacing the `ngDoCheck` watcher (F9).
- A slow earlier answer never replaces a newer one (a spec with out-of-order responses).
- A failed preview shows its own message and a retry, separate from an empty list.
- Each row shows a pending state while its preview loads.
