# F9.10 UI structure and honesty

**Epic:** E9 Web app UI (core screens)  
**Phase:** MVP for the quick fixes, v2 for the rest

A planned refactoring of the Angular app from the code review: stop linking screens that are not built, say when a load failed, give the biggest pages one job each, and move the matching rules the UI copied out of the client so the server decides and the screen only shows it. Low findings not covered here (full i18n, account-menu keyboard access, bell focus trap) wait until the copy stops moving.

Source: the 2026-11-11 design reviews in `Testing/Scenarios/Results/` (`DESIGN-REVIEW-2026-11-11-StuffIt_UI-code-review.md`, `DESIGN-REVIEW-2026-11-11-StuffIt_API-matching-confidence-scoring.md`). Finding ids (F1...) are the UI review's. Check each claim against the code before starting: the reviews were read-only and the code moves.

**Order:** S9.10.1, 9.10.2, 9.10.3, 9.10.9 and 9.10.11 first (small, no API change). Then 9.10.7 and 9.10.8. Then the contract (S2.8.4, S2.8.5) with 9.10.4 to 9.10.6 together. The big splits (9.10.10, 9.10.12) come last because they are mechanical once the helper exists.

**Rules for every story here:** behavior-preserving unless the story says otherwise; existing specs stay green and are not loosened; no NgRx; targeted tests while building, full suites before the push.
