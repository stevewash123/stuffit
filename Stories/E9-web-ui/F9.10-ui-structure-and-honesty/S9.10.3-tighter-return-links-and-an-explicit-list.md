# S9.10.3 Tighter return links and an explicit list of anonymous calls

**Feature:** F9.10 UI structure and honesty  
**Phase:** MVP  
**Depends on:** none

As a **person signing in**, I want a sign-in link to only ever send me inside the app, and a bearer token never to leave with an anonymous call.

## Acceptance criteria
- A return address is parsed and accepted only when it resolves to an internal route; protocol-relative, backslash and encoded forms are refused (F14).
- The calls that never carry a token are an explicit set shared by the interceptor and its spec, including Google sign-in, signup verification and account switch.
- The share-target worker refuses a file over a stated size instead of caching it (F15).

## Status
Built (Push 65). safeReturnUrl reads the address as a browser does (backslash, tab and newline forms are refused). The calls that carry no token are one exported list covering every anonymous AuthController route, with a spec that sends each one. The share-target worker keeps at most 10 files of at most 10 MB (the API's own limit).
