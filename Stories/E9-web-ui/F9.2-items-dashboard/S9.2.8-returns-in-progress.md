# S9.2.8 Returns in progress

**Feature:** F9.2 Items list & dashboard  
**Phase:** MVP candidate (built first slice 2026-10-03)  
**Milestone:** M5/M6  
**Depends on:** S9.2.3 (Item detail page); S5.4.7 (track a return); the mark-as-returned record  

As a **user**, I want a list of the things I have decided to return, so when I am headed to a store I can see exactly what to take back.

## Acceptance criteria
- On an item, **Start a return** puts it on the returns-in-progress list. The item stays owned and its reminders keep running (the return window still matters). A note on the item says a return is in progress, with **Mark returned** and **Cancel return**.
- A **Returns in progress** page lists those items, closing soonest first, with the store, price, purchase date and how long the return window has left. It is reached from the items page.
- **Group by store** turns the same list into one section per store (A to Z, unknown store last) with item count and total value, so the user can say "I am going to Walmart today, what do I take back?".
- Marking the item returned (form: date, refund, method, how hard it was, problems) removes it from the list. Cancelling removes it without a record. Editing the item does not drop the return.
- Empty state explains how to add something.

## Built
Start and cancel on the item page, the list and group-by-store toggle, API `POST/DELETE /api/items/{id}/return` and `GET /api/returns/in-progress`.
