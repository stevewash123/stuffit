# S9.2.10 Archive items with no coverage left

**Feature:** F9.2 Items list & dashboard  
**Phase:** MVP candidate  
**Milestone:** unassigned  
**Depends on:** S9.2.1 (items list, status filter); S9.3.3 (delete or archive a purchase)  
**Related:** S9.2.11 (attention levels and the groups); S9.8.5 step 6 (bulk dismiss on New Items; share the multi-select pattern and the bulk endpoint shape); S9.2.9 (shared list controls); S5.1.1 (item search)

As a **user**, I want a view of My Items whose warranties have all run out, and to select several and archive them at once, so the list holds only things that still matter. If I search for one later, I can still find it and see what expired.

## Decision (Steve, 2026-10-19)
Archive, not delete. An archived item leaves the everyday list but is kept, with its coverage history and files, so a later search can pull it up to show what had expired and when. Permanent delete stays a separate, deliberate act on a single item (S9.3.3).

## Acceptance criteria
- A "No coverage left" filter on My Items, one click from the status filter and in the address bar like the other filters. It shows items where every coverage has ended: a manufacturer warranty, an added plan, a card benefit or a store return window all count, so work gloves leave the main list once their return window closes. A recently expired item counts the same as an old one, as long as nothing else applies. An item with no coverage on it yet (status "needs info") is not shown, because coverage may still be added.
- In that view, each row has a checkbox, plus "Select all" (the rows on screen, with a count) and "Clear selection".
- With one or more selected, an "Archive (N)" action appears. It asks for confirmation that says how many items will be archived and that they stay searchable. Nothing changes until confirmed. Archive is reversible, so the confirmation is light.
- Archived items are hidden from the default My Items list, the dashboard counts and the reminders (an item with no coverage left has none to send anyway).
- Search (S5.1.1) finds archived items and marks them "Archived". Their item page shows the coverage that expired and its end date.
- An "Archived" filter lists them, with the same multi-select so they can be restored ("Unarchive (N)") or permanently deleted ("Delete (N)", confirmed, with the count and a warning that files go too).
- The result is reported: "12 items archived", or which ones failed and why. One failure does not stop the rest.
- The list updates in place and keeps the filter and scroll position.
- Archiving does not let a receipt rescan make the item again: an archived item still counts as tracked (S9.8.5 step 3b). A permanently deleted one may come back on a rescan, and the delete confirmation says so when the item came from a receipt scan.
- Phone layout: the checkboxes and the action bar work with a thumb, and the bar stays visible while scrolling.
- Only my own account's items can be selected; an id from another account is ignored.

## The groups, colours and the minimum
See S9.2.11. This story is only the archive view and its multi-select; S9.2.11 says which items are Covered, Return window only, Coverage ended or Needs you, and how they are coloured. This view selects Coverage ended only (Expired and NoCoverage). A `NeedsInfo` item is never selectable.

## Decided (Steve, 2026-10-19)
- Recently expired is expired. There is no grace period; it counts when no other coverage applies.
- A store return policy is coverage. When it and every warranty have ended, the item has no coverage left and may be archived.
- Adding coverage to an archived item (an extended plan) brings it back to the list on its own.
- Archive is its own flag, not the returned or disposed statuses, since an archived item may still be owned.

## Notes for the build
- The items filter already has an `expired` status. Check "all coverages ended" against `ItemBrowseTests`, and add the no-coverage case.
- Archived is a flag on the item (for example `ArchivedAt`), applied as a default exclusion in `GET /api/items`, the dashboard and the reminder scheduler. Search and the Archived filter opt in.
- One endpoint, `POST /api/items/archive` with a list of ids and a restore counterpart, returning per-id results. Cap the batch (for example 200). The S9.8.5 bulk dismiss could share the shape.
- Tests to add: the filter's edges (one expired and one active coverage is not shown; no coverage; returned or disposed); archive hides from list, dashboard and reminders but not from search; restore; a batch that includes another account's id; a rescan does not remake an archived item; a UI spec for select-all and the confirmation count.
