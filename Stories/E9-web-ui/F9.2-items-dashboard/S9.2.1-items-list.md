# S9.2.1 Items list with coverage highlights

**Feature:** F9.2 Items list & dashboard  
**Phase:** MVP  
**Milestone:** M4  
**Depends on:** S3.1.1 (Add or edit a coverage (snapshot of terms))  

As a **user**, I want to see all my items and which are covered.

## Acceptance criteria
- Each row: name, seller, purchase date, price, nearest coverage end date
- Status badge per item: active, expiring soon, expired, needs info
- Sort by expiry, purchase date, name; filter by status, seller, manufacturer, category
- Text search across items (shared with F5.1)



Note (S1.3.7, draft): the list will probably default to my own items, with a way to show other people's, and must never show a private item to someone who cannot see it. Settle S1.3.7 before building this list.

## Deferred: facet counts from the API

Today the UI builds the store and brand choices, and their counts, by fetching the whole unfiltered item list. That is fine for a few hundred items. Two limits follow:
- **Counts don't narrow.** They are counts across all items, so they stay the same as filters are ticked. A shop's facets show how many results each choice would leave.
- **Whole-list fetch.** With thousands of items the extra request is wasteful, and the whole list travels just to build the filter panel.

Build when either starts to hurt:
- `GET /api/items/facets` takes the same filters as `GET /api/items`. For each of status, store, brand and category it returns `{ id, name, count }`, counting items that match every filter except that facet's own. Ticking Dyson then still shows the other brands with their counts, so a user can add a second brand.
- Choices with a count of 0 are hidden, except ones already ticked.
- The Items page calls it instead of the second `GET /api/items`, and re-calls it when the filters change.
- Category becomes a facet in the same panel, if the category list has grown past a handful.
- Done when: each choice's count equals the number of rows the list returns for it, tested in `ItemBrowseTests`, and the unfiltered full-list request is gone from the page.

Update 2026-10-19: Rows for items whose warranty is unconfirmed are highlighted (Warning), with a different mark for items expiring soon, and an item at or over the minimum nearing the end of its return window turns Error. The rules (colours, the two values of a line, per-person minimum, dismiss confirmation) are in S9.2.11.
