# S9.2.9 Group, filter and search on every list

**Feature:** F9.2 Items list & dashboard  
**Phase:** deferred (idea from Steve; decide the shape before building)  
**Milestone:** unassigned  
**Depends on:** S9.2.1 (items list); S9.2.8 (returns in progress); the lists that exist by then  

As a **user**, I want the same ways to group, filter and search on every list in the app, so I learn them once.

## The question
Each list so far grew its own controls: the items list has search, status, sort, store, brand, category and "everyone's items"; returns in progress has only a group-by-store switch; notifications, cards, stores and brands have their own. Before adding more controls one list at a time, decide one pattern.

## To decide
- Which lists get which controls. Likely a shared set: search box, group by (store, brand, category, status, person), a small filter row, sort.
- One control component and one convention for the address bar (links and the browser Back button keep working, as the items list already does).
- Defaults per list (items: by ending soonest; returns: closing soonest; notifications: newest).
- A saved view ("Walmart run") if people ask for it.
- Phone layout: controls collapse behind one "Filter" button.

## Acceptance criteria (draft)
- A shared list-controls component used by items, returns in progress, notifications, cards, stores and brands.
- Group by works on any list that has a natural grouping, with counts and totals where money is involved.
- Filters and grouping are in the address bar.
- No list keeps its own private version of a control the shared one covers.
