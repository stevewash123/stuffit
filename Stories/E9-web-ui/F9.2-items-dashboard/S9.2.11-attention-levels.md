# S9.2.11 Attention levels: what needs me, by value and deadline

**Feature:** F9.2 Items list & dashboard  
**Phase:** MVP candidate  
**Milestone:** QA  
**Depends on:** S9.8.5 (the per-person tracking minimum); S9.9.1 (New Items list); S9.2.1 (Items list); S3.1.6 (uncertain dates)  
**Related:** S9.2.10 (archive items with no coverage left); S9.9.4 (Dismiss); S9.9.5 (nav count); S4.2.1 (digest content); S2.2.12 (leave out services); S3.1.8 (return and transfer terms)

As a **user**, I want the app to show which items still need me, how badly, and by when, so a $250 monitor I never finished adding stands out and a $4 tube of glue does not.

This is the one place the rules live. The other stories point here.

## The two values on a line
- **Warranty value** uses the **unit price**, because warranties are per unit. It decides whether a warranty is plausible, so whether to ask about one. Wooden studs have none, so the person is never asked.
- **Return value** uses the **whole line total**, because a return takes back the whole line. 24 studs at 110.16 are worth recovering if a project is cancelled.
- **Severity** compares the person's tracking minimum with the line total (what is at stake). The unit price decides only whether a warranty question is asked.
- A line with no price counts as at or over the minimum, since we cannot show it is small.

## The minimum is per person
The minimum (default $50, `SmallItemThreshold` in `appsettings.json` today) is a setting of each person (S9.8.5, S9.8.3), not of the account. In a shared account each person sees their own colours and sorting for the same items.
- A new household member starts from the account owner's value (decided 2026-10-19), copied when they join, and changes it on their own afterwards. A single user starts from the default.
- Reminders and the digest use the recipient's own minimum.
- Changing it recolours at once. Colours are worked out when the list loads and are never stored on the item.
- Focus: single user first. Multi-user is left room for, not tested in depth: it is built so that nothing needs redoing (the setting belongs to the person, colours are worked out for the viewer), and the friction points of shared accounts are to be found in real use, not designed up front.

## The groups
Grouping is by what we know about coverage, not by price. Price only decides which group a new item starts in. They map onto the badges in `ItemQueryService.Classify`.

| Group | Badge today | Main list | Archive filter (S9.2.10) |
|---|---|---|---|
| Covered | Active, ExpiringSoon, MayBeCovered | yes | no |
| Return window only | Active or ExpiringSoon with only a Return coverage; includes a consumable at or over the minimum | yes, until the window closes | no, then yes |
| Coverage ended | Expired, NoCoverage | no, once archived | yes |
| Needs you | NeedsInfo (no coverage, nothing reviewed) | yes, highlighted | never |
| Smaller things | a waiting line in New Items under the minimum | n/a | n/a |

Ended is not the same as unknown. "No coverage left" means we know it ended. A `NeedsInfo` item may still hold a warranty nobody looked for.

## Colours
Every colour also has an icon and a short label, so nothing depends on colour alone (colour-blind users, the themes of S9.8.2).

| Where | Condition | Level |
|---|---|---|
| New Items | needs verification, line total at or over the minimum, or price unknown | Error |
| New Items | needs verification, under the minimum | Warning |
| New Items | nothing to check | none |
| My Items | warranty unconfirmed (`NeedsInfo`, or "may be covered") | Warning |
| My Items | unconfirmed, at or over the minimum, and the return window closes within 7 days | Error |
| My Items | expiring soon | its own hue and icon, apart from warning and error |
| My Items | unconfirmed and expiring | the worse colour, with both labels |

- **Needs you shows in both lists.** A big item can be waiting in New Items, or in My Items because it was Quick Added unfinished.
- **The deadline is the return window.** The label says when it closes ("closes in 12 days"), and turns urgent in the last 7 days. For a consumable it says what is recoverable ("closes in 12 days, 110.16 to recover") instead of "warranty unconfirmed".
- **Return-only items.** A consumable at or over the minimum carries only the store's return window. It shows as "Return window only", is not asked a warranty question, and Quick Add needs only its name confirmed. When the window closes the item has no coverage left and can be archived.
- **Past the window.** An unresolved line under the minimum is offered for bulk Dismiss ("9 items past their return window"). One at or over the minimum stays at Error, because a warranty may exist.
- **Smaller things stay collapsed** under one header with a count, in Warning, so a long hardware receipt does not paint a dozen amber rows.
- **The nav badge** (S9.9.5) counts Error-level items only.
- **Digest** (S4.2.1): Error-level items go in as "2 high-value items need checking; the return window closes Friday".

## Dismiss, archive and delete
- Dismissing one item at or over the minimum that still needs verification asks first: "Dismiss this high-value item that still needs checking?" Under the minimum, no question.
- In multi-select, "Select all" skips those items and says "2 high-value items skipped". They can still be ticked by hand, and that asks for confirmation naming them and the count.
- Dismissed is restorable, so the wording says dismiss, not delete.
- `NeedsInfo` items are never selectable for archive (S9.2.10). Permanent delete always confirms, with the count.

## Acceptance criteria
- A pure function takes the person's minimum, the line (unit price, line total, kind, return window) and the badge, and returns the level, the label and the deadline. Deterministic and unit tested; no live service.
- The Items list and New Items use it; the list rows show level, label and icon.
- The tests cover: price unknown; unit price under and total over (studs); under both; at the minimum exactly; return window 7 days and 8 days; two people with different minimums seeing the same item; changing the minimum recolours; Select all skips high-value unresolved items.
- Reads in the user's currency (S9.8.3).

## Colours chosen (Steve, 2026-10-19)
Traditional meanings, leaning pastel: a soft tinted background for the row with a stronger edge and icon, and dark text that keeps its contrast. They are theme tokens (S9.8.2), with a light and a dark value each; the values below are starting points, checked for contrast when built.

| Level | Meaning | Light background | Edge and icon | Icon |
|---|---|---|---|---|
| Error | high value, still unresolved | #FBE4E4 (soft red) | #C0392B | circle with an exclamation mark |
| Warning | unconfirmed, or under the minimum | #FFF3CD (soft amber) | #B7791F | triangle |
| Expiring soon | coverage about to end | #DCEBFA (soft blue) | #2F6DB5 | clock |

- Dark theme: the same hues as deep, muted tints with light text (for example #4A2626, #4A3F1C, #1F3550).
- Covered and Return window only items keep the plain row, so colour only ever means "look at me".

## Decided
- An item at or over the minimum with no known return window stays at Error until the person settles it. The row shows its age ("waiting 23 days") so it does not read as new.
