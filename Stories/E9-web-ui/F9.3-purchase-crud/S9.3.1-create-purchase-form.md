# S9.3.1 Create a purchase

**Feature:** F9.3 Purchase create / edit / delete  
**Phase:** MVP  
**Milestone:** M3  
**Depends on:** S2.1.1 (Add a purchase with one or more items); S2.1.2 (Attach receipts, manuals, photos); S3.3.1 (Add a card); S9.5.1 (Pick a party or create one inline); S9.1.3 (Inline quick-add, expand for details)  

As a **user**, I want to add a purchase with items in one form.

## Acceptance criteria
- Seller picker with inline "add new seller" (F9.5)
- Card picker from my cards, or none
- Inline essentials per purchase: seller, date, total; per item: name, manufacturer
- Expand or pop-out adds category, model/serial, order ref, notes, photos, per-item price
- Add multiple items; manufacturer and category pickers per item
- On save, proposed coverages are shown for confirm/edit (S3.1.2)
- Receipt upload on the same screen


## Status
Done (M3): essentials inline (store, date, card, item, brand, category); total, order number, model, serial, price in drawers; receipt attached on the same screen and uploaded after saving.

## Update (2026-10-03): item first, with known models

The form now starts with **What you bought**: **Brand (optional)**, then **Model / name**, then Category; **Where and when** (store, date, card) and the receipt and paperwork follow. When a brand is picked, the models it makes appear as an optional drop-down on Model / name (a browser suggestion list: it never limits what can be typed). Picking a known model fills in the model number and, if empty, the category, and saves the item name with the brand in front ("Pflueger President 2500"); a name typed freehand is kept exactly as typed. Data: new `product_models` table (global rows plus private ones per account), `GET /api/models?manufacturerId=`, seeded from `reference-data.json` (`models`). Seeded so far: Pflueger President 1500, 2500, 3500 and 4500, plus President XT, Supreme XT, Trion, Medalist and Patriarch (hand-entered, to check against Pflueger's catalogue). New categories: Fishing, Fishing reels.

Not done: a way for the user to add a model that is missing (private to their account, the table already allows it), admin editing of models (S7.5.x), and model lists for other brands. Brand-level defaults (a brand that makes one kind of thing sets the category) are not used on this form yet.
