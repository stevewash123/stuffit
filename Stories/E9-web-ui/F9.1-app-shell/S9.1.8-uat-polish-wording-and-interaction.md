# S9.1.8 Small wording and interaction fixes from UAT

**Feature:** F9.1 App shell & navigation
**Phase:** MVP
**Status:** Open (UAT 2026-11-02, issues 13 and 14). Not built. Batch these; none is urgent alone.

As a **user**, I want forms and menus to behave the way I expect, so that small roughness does not make the app feel unfinished.

## Acceptance criteria
- Validation: an empty form flags every required field, and a bad date names the field and the problem; the generic "One or more validation errors occurred." banner never shows alone (insurance, plan forms).
- The account menu opens on the first click.
- Typing a store name and leaving the field selects it, or clearly shows it was not selected; today only clicking the dropdown option works.
- "Stop covering", file delete and similar one-click removals ask first, or offer Undo.
- A delete dialog has one "Delete policy" button that a screen reader can tell from the page's own button.
- /settings/security redirects a non-administrator, instead of showing "You cannot do that."
- Wording: no stray space in "since Nov 2, 2026 ."; "1 item, which cost" reads correctly; a file's size is the same before and after upload (4 KB vs 3 KB); "Brand (maker)s" in the shared-data filter (S7.1.1).
- The "A new version of WarrantyBank is ready" banner does not show on a fresh page load.
