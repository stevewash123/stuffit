# S6.1.3 Card terms research agent

**Feature:** F6.1 Candidate policy queue  
**Phase:** v2  
**Milestone:** M7  
**Depends on:** S3.3.4 (the search flow and `ICardPolicyFinder` stub); S6.1.1 (candidates); S7.6.5 (LLM integration and cost control)  

As an **operator**, I want the card-terms search to be done by an agent that reads the issuer's own documents, so a user's search returns real, sourced terms.

## Acceptance criteria
- Implements `ICardPolicyFinder` with no change to the S3.3.4 API or UI
- Finds the card's Guide to Benefits (issuer site; card or network tier, e.g. Visa Signature, World Elite Mastercard), renders script-driven pages in a headless browser, and extracts PDF text with a PDF parser (not a page summarizer)
- Returns, for extended warranty, purchase protection, return protection and price protection, either the terms or "none" (the guide lists no such benefit)
- **Every number comes with the verbatim sentence and URL it was read from.** A term with no quote is dropped as not found. The agent never fills a gap from memory or from a review site
- Review sites and forums can point to the right document but are never the source
- Notes that benefits vary by card tier or by network, and which tier was matched
- Stops at a limit of steps, seconds and cost per search (settings); on the limit it returns what it has, marked partial
- Logs the pages visited, tokens and cost per search (S7.6.5)
- Evaluated on a fixed set of cards with known-good terms: the 12 seeded in October 2026 plus the unresolved ones in `docs/card-policy-worklist.md`. Measure: terms correct, terms wrong, and not found. **Wrong must be zero**; not found is acceptable
- Results go to the candidate queue (S6.1.1), never straight to reference data. Promotion needs operator verification or N matching user confirmations

## Notes
- Candidate frameworks: Microsoft Agent Framework (successor to Semantic Kernel and AutoGen, as far as we know; confirm) or the Anthropic SDK with tool use. Decide when this story starts
- A scheduled sweep that runs this over every catalog card is a separate story under F6.4
