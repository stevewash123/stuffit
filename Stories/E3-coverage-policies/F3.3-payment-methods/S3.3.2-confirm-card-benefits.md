# S3.3.2 Confirm card benefits

**Feature:** F3.3 Payment methods & card benefits  
**Phase:** MVP  
**Milestone:** M2  
**Depends on:** S3.3.1 (Add a card); S3.2.1 (Party and versioned policy tables)  

As a **user**, I want to review and confirm the benefits my card has.

## Acceptance criteria
- Reference benefits proposed for the card product
- User edits term, cap and claim window and confirms
- Stored per card with confirmed_at (payment_method_benefit)
- Coverage from a card snapshots the confirmed benefit as of purchase date


## Status
Done (M2): proposed benefits from reference data, edited and confirmed by the user, stored with a confirmed date. Coverage snapshotting at purchase arrives in M3.

## Added 2026-10-03 (owner request): warn when benefits are not confirmed
A card's benefits only count once the user confirms them, and a new card starts with none, so a purchase on it silently gets no card coverage. The user is told wherever it matters:
- On Add a purchase, as soon as a card with no confirmed benefits is chosen: a notice with "Review card benefits", opening the card in a new tab so nothing typed is lost; it clears when the user comes back with the benefits confirmed.
- On the item page, for a purchase paid with such a card (the purchase detail carries `cardBenefitsUnconfirmed`).
- Later, as a message if it is still not done (S4.6.3).
Built 2026-10-03 (the two screens and the API flag; tests added). Known gap: a card whose owner confirmed "no benefits" cannot be told apart from one never reviewed, so it keeps showing the notice. Fixing it needs a "reviewed on" date on the card, which is a migration, so it waits for the desktop merge. Also a card saved as plain "Chase Freedom" matches none of the catalog's Freedom cards (Unlimited, Flex, Rise), so no benefits are proposed; asking which card it is belongs with S3.3.6.

## Added 2026-10-04 (owner request): the bell keeps a standing notice
Until at least one card has confirmed benefits, the bell carries an active notice: a count on the badge (added to the unread count) and a highlighted entry at the top of the dropdown that links to the card (or to the card list when there are several or none). It is not a message that is read and cleared; it is worked out from the cards, so it clears the moment one card is confirmed and returns if that stops being true. With no cards at all it asks the user to add one and confirm it. Built 2026-10-04 (`SetupNoticesService`, bell, card page; 9 specs).
Open question for the owner: a user who pays only in cash will see this notice for good. Say if there should be a "I don't use cards" way to turn it off.

## Added 2026-10-04 (owner request): card tracking is optional
Card benefits are a big feature of a warranty tracker, but not everyone uses them, so nothing about them may nag for good. The bell notice has an "I don't use credit cards" button that turns off both the bell notice and the "Card benefits to confirm" messages in one step. It reuses the notification preference for that message type (so no new storage, and it can be turned back on in Settings, Notifications). Built 2026-10-04; this settles the open question above.
Also built: a card saved under a name we do not list ("Chase Freedom") now shows "Is yours one of these?" on its page, with the listed cards whose names contain every word (Freedom Unlimited, Flex, Rise), and saving one finds its benefits.
