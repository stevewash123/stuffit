# S3.3.4 Search the internet for a card's terms

**Feature:** F3.3 Payment methods & card benefits  
**Phase:** MVP (flow and stub); the real search is S6.1.3 (v2b)  
**Milestone:** M4  
**Depends on:** S3.3.1 (Add a card); S3.3.2 (Confirm card benefits)  

As a **customer** who added a card we have no policies for, I want to ask WarrantyCat to look up its purchase benefits, so I do not have to find and type them myself.

## Acceptance criteria
- A card with no policies on file (a catalog card with none, or "not listed") shows **Search the internet for this card's terms** on its card page, and on its row in the cards list
- Pressing it shows a progress state with a spinner, the card name, and "This can take up to a minute". The page stays usable and the user can leave and come back
- The request goes to `POST /api/cards/{id}/policy-search` and returns at once with a search id. The UI polls `GET /api/cards/{id}/policy-search/{searchId}` (status: `running`, `found`, `nothingFound`, `failed`); `GET /api/cards/{id}/policy-search` returns the newest search so the page can resume after the user leaves (paths are under `/api/payment-methods`) until it ends or 90 seconds pass, then says it is still working and offers to notify
- A **found** result opens the existing confirm-benefits editor (S3.3.2) pre-filled with the proposed terms. For each term it shows the source link and the quoted sentence it came from. Nothing counts until the user confirms
- **nothing-found** says so plainly and offers to enter the benefits by hand (S3.3.2). It never implies the card has no benefits
- **failed** shows a short message and a Retry
- One search at a time per card; a repeat press while one is running reattaches to it. Limited per account per day (setting, default 5)
- The search runs behind an `ICardPolicyFinder` interface. **In this story it is a stub**: it waits 3 seconds and returns a fixed result for a few known card names, and nothing-found for the rest (a setting can force `failed` for testing). No LLM and no web calls
- Each search is stored (`card_policy_searches`: card, status, started and ended times, result terms with source URL, quoted text and found date). The finder never writes seed or global data. When the real agent arrives (S6.1.3), its results also go to the candidate queue (S6.1.1)

## Notes
- The user's own card details (nickname, last 4) are never sent to the finder. Only issuer and card name
- A confirmed user result is a crowd submission: it counts toward N matching reports (F6.2) and, once verified, becomes shared reference data
- Time limit and spinner copy are settings, not code
