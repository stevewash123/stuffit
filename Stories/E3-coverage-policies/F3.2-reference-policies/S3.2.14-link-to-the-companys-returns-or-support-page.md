# S3.2.14 Keep a link to the company's own returns or customer support page, and use it in guidance

**Feature:** F3.2 Reference policies
**Phase:** v2
**Depends on:** S3.2.5 (policy source and confidence), S3.2.9 (research in rounds), S3.2.11 (not returnable); feeds S5.4.1 and S5.4.14 (general guidance)

As a **person who needs to return something or make a claim**, I want WarrantyCat to point me to the company's own page about returns or customer support, so I start from the real place, not a search.

As the **operator researching a store or brand**, I want the page the research already opened to be kept, so the link costs no extra research.

## Why
Today the research opens a store's own site to read its return policy (`ReturnPolicyFinder`, S3.2.5; `WarrantyFinder` for makers), and the policy keeps only the page the *terms* were read from. The same visit passes the page that says **how** to start a return (a returns portal, "start a return", the print-a-label page) and the support contact page. Keeping them costs almost nothing now, and it lets general guidance say "start here" without gathering per-company steps (the heavy data work). Where the company is known but its guidance is not, WarrantyCat shows only the general words, as today.

## Acceptance criteria
- A shared store or brand can carry up to two links, each an `https` address, each optional:
  - **Returns page**: where the company explains how to return or start a return (a store), or how to make a warranty claim (a maker).
  - **Customer support page**: where the company's contact options are.
  Both are kept on the company (the shared party), not on a single policy, so one link serves every policy for that company. A private company an account added itself may carry them too (never shared).
- **Collected in the same visit as the policy.** The existing finders that open the company's site (return policy for stores, warranty for makers, S3.2.5/S3.2.9) also report the returns page and the support page they came across, each with the sentence or link text it relied on. As with every suggestion, nothing is saved until an operator opens the page, sees it is the right one, and confirms; a link that is not `https`, that was not on the company's own site or domain, or whose page cannot be opened is not offered.
- **The operator can add, change or clear** each link on the shared-brand and shared-store screens, with the page the link was read from as evidence (an official-source record, like S3.2.5). A link is never edited silently by a later research round: a changed address is a proposal the operator confirms.
- **Round data files** (`reference-data/*.json`, S3.2.9) accept the two links per store or brand (`returnsUrl`, `supportUrl`); the import validates them (https, plausible host), is safe to run again, and records the evidence. A file with neither link imports as today.
- **General guidance uses them when present** (S5.4.1 how-to card, S5.4.14 the result): for a return, the card shows "Start with <company>'s returns page" with the link; for a warranty claim on a maker, "<company>'s warranty and support page". When the company has only a support page, that is offered with the words "customer support" (never called a returns page). When neither is known, the guidance reads exactly as it does today; no empty link, no search link made up.
- A link is shown as the company's own page and opens in a new tab. The wording says **WarrantyCat** where WarrantyCat speaks; nothing says the page is current or promises what it says (the person reads it).
- **Check for rot:** each shared link keeps the date it was last confirmed. A link more than 12 months unconfirmed is still shown, labelled "Check that this page is still current", and joins the operator's list of things to re-confirm (S6.4.1 later; not built here).
- **A private-sale seller has none** (no company); a seller with S3.2.11 "not returnable" still shows its support page if known, never a returns link.
- The shared-reference export and the person's data export include nothing new for the person (these are company data); the operator's reference export includes the links with their evidence.

## Notes
- This is not per-company steps or eligibility (S5.4.2, S5.4.13). It is only the front door. Where the research is already done, the link is a free by-product.
- The existing `Party.ClaimUrl`/`ClaimPhone` (the plan or warranty provider's own claim contact, S3.4) stay as they are. Decide while building whether the maker's **claim** page belongs in `ClaimUrl` (reuse it) or the new returns field; do not create two fields that mean the same thing.
- Start with the stores and brands already seeded (S3.2.9 rounds): a one-time pass over their sites using the same finders fills most links; the rest stay empty and show nothing.

## Status
Built 2026-11-06 (API and UI on feat-links, not merged). Migration PartyCompanyLinks (parties: returns_url, support_url, their confirmed_at dates, claim_url_confirmed_at).
Decisions: a maker's warranty-claim page IS the existing Party.ClaimUrl (no second field; it already fills the maker's coverage contact); a store's returns page is the new ReturnsUrl; a party that is both keeps both. The API calls the first slot "returnsUrl" on the admin screens and in data files (a brand that is not also a store maps it to ClaimUrl). Guidance shows the page on the claim-wizard result (the how-to card today): a Return option gets the seller's returns page, a Manufacturer option the maker's warranty and support page, a store's own warranty and a store with no Return option get support only. Evidence is a PolicyEvidence row of new type CompanyLink (PolicyId = the party). A link is kept only if https, a plausible host and on the company's own site when its website is known. No operator reference export exists in code, so the operator's list rows (admin stores and brands) carry the links, dates and evidence page.
Tests: unit CompanyLinksTests, LinkScoutTests, ReferenceDataFilesTests (links); integration CompanyPageGuidanceTests; reference-suite CompanyLinksTests (not run as a suite); UI company-links via stores.page.spec, brands.page.spec, claim-wizard.page.spec.
