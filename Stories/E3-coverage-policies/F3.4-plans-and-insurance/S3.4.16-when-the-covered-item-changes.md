# S3.4.16 When the covered item is returned, replaced, sold or dies

**Feature:** F3.4 Plans and insurance you hold  
**Phase:** v2  
**Milestone:** M8 (proposed)  
**Depends on:** S3.4.2 (plans); S2.4.13 (plan refund); S5.4.20 (mark returned); S3.4.15 (cancel a plan); S3.4.8 (service requests)  
**Found by:** Steve, 2026-11-03.

As a **user** whose item has a plan, I want the app to ask what happens to the plan when the item changes, so I do not keep a plan on a thing I returned, or lose a plan that carried over to the replacement.

## Why this matters
Plans often replace a broken item with a new one and keep running on the replacement. Other plans end with the item. Today deleting an item silently drops it from the plan (S3.4.2), and Mark returned is silent about a plan bought with the item (S5.4.20 lists "ending a protection plan returned with its item" as not built).

## Acceptance criteria
- **Mark returned** on an item with a plan asks: *Did you return the plan too?* **Yes, refunded** (records the refund, S3.4.15; ends the plan on the return date), **Yes, no refund**, **No, I'm keeping it** (the plan stays and is flagged "covers an item you returned": a to-do to cancel or move it), **Not sure** (to-do). A plan bought with the item defaults to "Yes, refunded" when the plan type says it is refunded with the item (S3.4.5).
- **Replaced under the plan.** A *Replaced by the plan* action on a covered item (from a service request, S3.4.8, or the item page): creates the replacement item (brand, model, serial editable, date today), and asks whether the plan **continues on the replacement** (default, with the plan's own dates unless the person changes them), **ends**, or **restarts** (new term from the replacement date). The old item is marked replaced, not deleted; its history and files stay.
- **Sold, given away, thrown away, lost** (S9.2 item states): asks the same *what about the plan* question; offers cancel (S3.4.15) when the plan is not transferable (plan type or contract says), and a transferable plan can be left on the new owner (ends covering this item, plan continues for others).
- **Deleting an item** that has a plan asks before dropping it from the plan, naming the plan.
- A plan left covering no items is shown as "Covers nothing" with options *Add items* / *Cancel* / *Keep*.
- Nothing here changes a plan without an explicit answer, and every answer is undoable for the session.

## Status
Built 2026-11-07 on branch feat-planform (API bfea9c0 / UI 79f54c5, not merged; migration ItemReplacedAndPlanAnswers: items.replaced_by_item_id, warranty_plans.keep_when_empty, item_plan_answers). Nothing here changes a plan without an explicit answer: an item with a running plan cannot be deleted, marked returned, marked disposed or replaced until each plan has an answer (the server refuses with 409 needsPlanChoice naming the plan, and asked-but-unanswered changes nothing). An ended or cancelled plan is not asked about.
Mark returned: the return form asks "Did you return the plan too?" per plan: Yes, refunded (amount required; records the refund and cancels on the return date), Yes, no refund (cancels on the return date, no refund to-do), No, I am keeping it (plan stays, flagged "Covers an item you no longer have" on the plan page and list, with a to-do), Not sure (to-do, nothing changes). Yes, refunded is ticked only for a plan read from the item receipt; nothing is ticked otherwise.
Replaced by the plan: a button on an item a running plan covers. It makes the replacement as a new item (name, brand, model, serial editable, date today, the people of the old item), then asks Carry on with the replacement (default, the plan own dates, which can be changed for a plan covering nothing else), End, or Start a new term from the replacement date. The old item is marked Replaced, links to the replacement, and keeps its history and files.
Sold, given away, thrown away, lost, it stopped working: Mark disposed asks what happened and then the plan question (cancel through S3.4.15, leave it with the new owner / take it off the plan, keep, not sure). Delete: names the plan; drop it from the plan or cancel it too. A plan covering other items is never cancelled, ended or restarted for one of them: only taking the item off it, keeping or not sure are offered, and the others keep it. A plan left covering nothing shows Covers nothing with Add items / Cancel / Keep (Keep is remembered until it covers an item again). Every answer is undoable: an Undo bar stays on the item page for the session and reverses the plans (cancelled plan re-opened, items put back, to-dos and dates restored) and the item.
Decisions where the story was silent: (1) there is no plan type yet (S3.4.5), so "transferable" and "refunded with the item" are not known: Yes, refunded is ticked for a plan read from the item receipt, and Leave it with the new owner is offered for a sale or gift with the note that whether a plan can be passed on is in its contract. (2) Disposed has no S9.2 sold/given-away states yet, so the question asks what happened (sold, given away, thrown away, lost, it stopped working) and uses it to word the answers; it is not stored on the item. (3) The replacement is a new purchase dated the replacement date with no seller, price or total. (4) A deleted item cannot come back, so Undo after a delete is not offered; a plan cancelled with it can be re-opened from the plan page. (5) Marking returned from a return receipt in New Items and recording a store refund do not ask: the plan stays, flagged on its page and list. (6) A vehicle part deleted with its vehicle drops off its plan without a question.
Not built: the service-request route to Replaced by the plan (S3.4.8 is not built); the item page button is the way in.
