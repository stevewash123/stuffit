# S3.4.18 Plan form: clear errors, no lost work, no accidental changes

**Feature:** F3.4 Plans and insurance you hold  
**Phase:** v2  
**Milestone:** M8 (proposed)  
**Depends on:** S3.4.2 (plans, "Start from the document")  
**Found by:** UAT 2026-11-02 and 2026-11-03 (FS-31 steps 2, 4, 14, 15, 17); Steve, 2026-11-03.

As a **user** filling in or updating a plan, I want errors next to the field that caused them, a warning before I lose typed work, and a document update that shows only what changed, so the form is safe to use on a phone.

## Acceptance criteria
- **Field-level errors.** Saving with required fields empty marks each one (company, name, start) with its own message and moves focus to the first. The banner "Choose the company that sold the plan." (one field only) and "One or more validation errors occurred." (raw API text, FS-31-4) are gone.
- **Date logic.** End before start is marked on the field, with the correction suggested; an end date counted from a term says so; a start in the future says "Not started yet".
- **Unsaved work.** Leaving the plan form (Cancel, back, navigation, closing the tab) with edits or a read document pending asks **Keep editing / Leave without saving** (FS-31-14).
- **Update from a newer document shows only differences** (FS-31-15): fields that are unchanged are not listed or ticked; new and changed fields are, each with old and new values and the quote. If nothing differs the page says so and offers nothing to accept.
- **A web address that is not a link** read from a document (FS-31-14: "www.example.com/shield") is offered with "https://" added as a suggestion, not rejected.
- **End this plan** asks for confirmation naming the number of items it will end on and the date; **Stop covering** and **delete file** keep their confirmations (present in build 982952c).
- **Company picker** distinguishes *sold by* from *serviced by* when both are known (S3.4.5) and explains the difference in one line.
- All of the above hold at phone width, with the keyboard open.
