# S3.1.7 The item page: read it, then edit it

**Feature:** F3.1 Coverage tracking  
**Phase:** v2  
**Milestone:** unassigned  
**Depends on:** S3.1.1; S3.1.2 (Propose coverages when a purchase is saved); S3.2.5 (Policy source and confidence)  

As a **user**, I want the item page to be a clear read of what I own and whether it is covered, and to change things only when I choose to edit, so I am never editing by accident and the first thing I see is the item.

Built 2026-10-04 from the owner's direction (stuffit8 review).

## Principle
View is for reading, edit is for changing. Every control that changes data appears only after the pencil at the top. A waiting suggestion is not hidden from the view, but acting on it is an edit.

## Acceptance criteria
- **Order, top to bottom:** the item and purchase facts first, then the card-benefits warning (when it applies), then Policies, then insurance, to-dos, receipts and files; "Start a return" last.
- **Item and purchase panel** shows only rows that have a value in the read view; in edit mode every row shows so it can be filled in.
- **Policies, read view:** a one-line summary that opens to the full list.
  - State: **Covered** (something still running), **Coverage ended** (everything has run out), **Not set up yet** (nothing confirmed). "Not set up" is not "not covered".
  - The policy to try first, and the next one to end with its date and time left.
  - Opened, it lists every confirmed policy with dates, terms and claim links already showing. No edit, remove or add controls.
  - When suggestions are waiting: "N suggested policies to review" and a Review button that switches the page into edit mode. There are no tick boxes or edit buttons in the read view.
- **Policies, edit mode:** the card becomes "Your coverage" and the Suggested coverage block (tick boxes, "Verify the above N policies apply", change, doesn't apply, not sure yet) appears above it. Confirmed coverage stays editable below, with Add coverage and Suggest coverage (brings back what was set aside).
- Suggestion confidence, the tick-by-default rule and quick add follow S3.1.2.

## Not in this story
- Moving coverage rules or confidence (S3.1.2, S3.2.5).
- Sharing or per-person views of an item (F1.3).
