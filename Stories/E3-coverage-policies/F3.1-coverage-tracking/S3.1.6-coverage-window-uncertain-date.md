# S3.1.6 Coverage from an uncertain date

**Feature:** F3.1 Coverage tracking  
**Phase:** v2  
**Milestone:** M6  
**Depends on:** S2.7.1; S3.1.2 (Propose coverages when a purchase is saved)  

As a **user**, I want coverage worked out sensibly when the purchase date is a guess.

## Acceptance criteria
- Coverage start and end are each a range when the date is a range; end earliest and end latest are both stored
- The app plans on the earliest end: reminders, "expiring soon" and the dashboard use it
- The coverage chip says "ends between Mar 2028 and Mar 2030 (date estimated)"
- If even the latest end is past, the coverage reads "probably expired" with what to try anyway (S2.7.7, S2.7.9)
- If the earliest end is past but the latest is not, it reads "may still be covered; confirm the date"
- Return windows (days) with an unknown date are shown as "check", never as open
- The snapshot records the date range it was computed from, so S2.7.12 can recompute
