# S7.1.7 Turn administrator two-step sign-in back on before deployment

**Feature:** F7.1 Admin console  
**Phase:** MVP (release gate)  
**Milestone:** M5  
**Depends on:** S7.1.5; S7.6.1  

As an **operator of the business**, I want administrator two-step sign-in enforced again before the first deployment, so the account that can change what every customer sees is never live with only a password.

## Why this exists
S7.1.5 built the protection. While the app is only running on a development machine, the enforcement is switched off (commented out, each place marked `TODO(S7.1.7)`) so the test administrator can open the admin screens straight after signing in. This story is the reminder and the checklist for switching it back on.

## Acceptance criteria
- Every place marked `TODO(S7.1.7)` in the API and UI is restored, and `grep -rn "TODO(S7.1.7)"` finds nothing left in `src`
- An administrator who has not set up an authenticator app is sent to Settings > Security first, and no admin screen opens until they have (the S7.1.5 behaviour)
- An administrator account with two-step sign-in set up is asked for a code at sign-in, and admin changes need a code from the last 10 minutes
- The tests skipped for the development period are un-skipped and pass (listed under Notes)
- The production administrator account has two-step sign-in enrolled and its recovery codes stored somewhere safe, before the site is opened to anyone
- A check on the deployed site: sign in as the administrator without a code and confirm the admin screens refuse

## Notes
Marked places and skipped tests are listed in the Status section so nothing has to be hunted for.
