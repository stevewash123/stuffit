# S7.1.9 Feedback and issues queue

**Feature:** F7.1 Admin console  
**Phase:** MVP  
**Milestone:** QA  
**Depends on:** S7.1.8; S7.1.3; S7.6.4  

As an **administrator**, I want customer questions, suggestions and problems in one queue I can work through, so nothing gets lost and customers get an answer.

## Acceptance criteria
- The admin navigation has a **Feedback** page (a placeholder exists now) with a count of new items; the admin home shows the same count (S7.1.3)
- Each item shows type (Question, Suggestion, Problem), message, who sent it, what they were looking at, any attachment, and how long it has waited; oldest first
- Status moves New, In progress, Answered, Closed. Each change records who and when
- The administrator replies from the page; the customer gets the reply by email (from the StuffIt sender, reply-to the support address) and in their sent-messages list (S7.1.8)
- Filters by type and status; search by sender or text
- A **problem** can be linked to a shared-data record (a store, a policy, a warranty document) so a "this warranty is wrong" report becomes a review item (S7.1.2) as well as a reply
- **Notification into issue:** an item that came from a customer's notification (S7.1.8) shows that notification beside the message. The administrator can also turn it into a tracked issue (a problem with a title, status and notes, separate from the conversation) so several reports about the same cause can be grouped under one issue and closed together
- Grouping reports under one issue lets the administrator reply to all of them at once when it is fixed
- Every status change, reply and merge is audited (extends the S7.1.5 audit trail)

## Notes
Open question: should the administrator also be able to create an issue from a system event that no customer reported (for example, a document reader that keeps failing)? Likely yes, as a later addition; the issue record is the same.

The administrator never reads another customer's notifications in bulk. The only notification content the administrator sees is the one a customer chose to attach (S7.1.8).

## Status

Partly built (branch uat-feedback, not merged). The Feedback page lists every account's messages newest first (not oldest first), with filters by status and type, a "new" count, and paging. Opening one shows the message, sender (email and name), page address, app version and item name, and the administrator can set the status Received, In progress or Answered; each change is audited (reference audit, who and what). Operator-only API: /api/admin/feedback.

Not built yet: Closed status, reply from the page and email to the customer, attachments, search by sender or text, linking a problem to a shared-data record, notification beside the message, tracked issues and grouping, the count on the admin home (S7.1.3) and in the navigation, the "when" of a status change (audit rows carry the time but the page does not show it).
