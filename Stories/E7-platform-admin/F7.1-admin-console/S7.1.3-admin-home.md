# S7.1.3 A different home for the administrator

**Feature:** F7.1 Admin console  
**Phase:** v2  
**Milestone:** M7  
**Depends on:** S7.1.2; S6.1.4; S6.6.3  

As an **administrator**, I want to land on a work queue when I sign in, not on a customer screen.

## Acceptance criteria
- An administrator signing in goes to the admin home; everyone else goes to the customer home
- Admin home shows what needs attention with counts: warranty documents awaiting review, submitted policies and candidates, disagreements and change signals, uploads flagged for personal information, stale or failing source checks
- Each count opens its queue; oldest first; items show who submitted, what, and the evidence side by side
- Admin navigation is its own set (queues, shared data, audit trail, credits when they exist), not the customer navigation
- Admin pages and endpoints stay protected on the server (already enforced by the Operator policy); hiding links is only a convenience

## Notes
The administrator flag already exists (is_operator, checked against the database on every admin request). Terminology: administrator in the product and docs; the column name can be renamed later.

## Status

Partly done: an administrator now lands on the admin area (`/admin`) after signing in, with its own header and navigation: Review (placeholder), Shared data, Feedback (placeholder), and an Admin badge. Not done: the work-queue counts on the admin home.
