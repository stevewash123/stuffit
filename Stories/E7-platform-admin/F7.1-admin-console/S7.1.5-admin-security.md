# S7.1.5 Protect administrator access

**Feature:** F7.1 Admin console  
**Phase:** MVP  
**Milestone:** M5  
**Depends on:** S1.1.1; S7.1.1  

As an **operator of the business**, I want to make sure administrator access is hard to misuse.

## Acceptance criteria
- Two-step sign-in (authenticator app) is required for any administrator account before it can open admin screens
- Shorter session and re-authentication for sensitive admin actions (publishing shared data, granting credits)
- Every administrator action is audited with who, what, when (extends the reference_audits trail)
- Administrators are granted only by another administrator or the command line, never by signup or an API a customer can reach
- Recommended: use a separate email for the administrator account from any personal customer account

## Notes
The administrator can change what every customer sees, so this account is the highest-value target.

## Status

Done (M5): Two-step sign-in with an authenticator app is required before any admin screen opens. TOTP written out (RFC 6238, tested against the RFC vectors) with replay protection: a code is accepted once only. Ten one-time recovery codes. Setup, QR code and key shown, first code confirms; it cannot be switched off through the API (another administrator runs `--reset-2fa email`, which ends all their sessions). Admin sessions are shorter: access token 10 minutes, sign-in cookie 24 hours, second-factor check good for 8 hours, and every admin change (publishing shared data, granting access) needs a check from the last 10 minutes; the UI asks for a code in a dialog and retries the request. Administrators are granted only by another administrator (fresh check, audited) or the command line (audited), never at signup. Every grant, removal, enrolment, failed code and re-check is written to the audit trail with who and when. Wrong codes count toward lockout. Settings > Security (administrators only). Tests: `TotpTests`, `AdminSecurityTests`, `privacy-security.spec.ts`, `reauth.spec.ts`. Not done: an admin screen for the audit trail of these events (they are recorded in `reference_audits`, entity type `admin-security`).
