# S7.7.3 Cards controller uses a service

**Feature:** F7.7 Code health  
**Phase:** MVP  
**Milestone:** M5  
**Depends on:** none  

As a **developer**, I want `CardControllers` to translate HTTP only, with the card rules in a service. It has the most direct queries of any controller (about 10 sites).

## Acceptance criteria
- A `CardService` (Infrastructure) owns the queries and rules; the controllers take it and the current user, nothing else.
- Responses, routes and status codes unchanged.
- The card logic has unit or integration tests that go through the service, not only through HTTP.
- `CardControllers` no longer references `StuffItDbContext`.

## Status
Done 2026-11-02 (API commit 6108b35). CardService (Infrastructure/Reference) owns the card queries and rules; the controllers take it and map results. Unit and card integration tests pass. Not done: a test that goes through the service rather than HTTP (the unit-test project has no database).
