# S7.5.6 DDL: notification and messaging schema

**Feature:** F7.5 Data foundation (DDL)  
**Phase:** MVP  
**Milestone:** M0  
**Depends on:** S7.5.5 (Migration tooling and seed scripts)  

As a **developer**, I want to create the tables behind the dispatcher, center, digests and unsubscribe.

## Acceptance criteria
- Tables: notification (S4.5.1 fields, indexed by user, is_read, created_at), notification_preference (user, type, channel, enabled, delivery_mode, lead_time), user contact (phone, verified, verified_at)
- pending_consolidation (user, type, item ids JSON, scheduled_for, job id, processing_started_at, sent_at, failed_at, failure_reason)
- batch_run (batch type, date, targets, successes, errors, duration) for digest idempotency
- email_unsubscribe_event for audit
- Unique constraints prevent duplicate preference rows and duplicate batch runs

Technical story. Schema ideas from ConsignmentGenie entities Notification, NotificationPreferences, PendingConsolidatedNotification.
