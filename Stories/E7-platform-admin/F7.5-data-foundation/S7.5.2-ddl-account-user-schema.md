# S7.5.2 DDL: account, user and billing schema

**Feature:** F7.5 Data foundation (DDL)  
**Phase:** MVP  
**Milestone:** M0  
**Depends on:** S7.5.5 (Migration tooling and seed scripts)  

As a **developer**, I want to create tenant, user and subscription tables.

## Acceptance criteria
- Tables: account, user, stripe_event
- Account carries stripe_customer_id, stripe_subscription_id, is_founder, founder_tier, cached_subscription_status, cached_period_end, plan features list
- stripe_event: unique stripe_event_id, account id (resolved via customer id), event type, raw payload, processed, processed_at, error
- Every user-owned table carries account_id; tenant isolation enforced (row-level security or query layer, decision recorded)
- Single customer role in MVP: every user is the same, so no role column on preferences, notifications, routes or screens
- Membership row (account_user) carries a role column defaulting to member, reserved for family (F1.3) and business (E8) features; nothing reads it yet
- Operator access (admin console, S7.1.1) is a separate is_operator flag on the user, not a customer role

## Notes
Technical story. ConsignmentGenie has owner, consignor, admin and customer roles, and role appears in preference keys, API paths and duplicate screens; this simplification removes all of that.
