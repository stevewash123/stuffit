# S7.6.3 Private file storage

**Feature:** F7.6 Technical foundation  
**Phase:** MVP  
**Milestone:** M0  
**Depends on:** S7.6.1 (Environments and deployment)  

As a **developer**, I want to store receipts and documents securely.

## Acceptance criteria
- Object storage (S3/R2) with private buckets
- Signed URLs for access, per-account key prefixes
- Virus scan or type/size validation on upload

## Notes
Technical story.

## Status
**Stubbed for development:** `IFileStore` is `LocalFileStore` (files on local disk). The real object-storage implementation (suggested Cloudflare R2), signed URLs and upload validation are not built. Receipts uploaded today do not survive a move to Render.


## Status update (2026-10-17)
`CloudinaryFileStore` is built behind `IFileStore` (`Storage:Provider=cloudinary`): private `authenticated` uploads under a per-app folder, read back with a signed request and streamed through the API, so there is no public link. Reuses the ConsignmentGenie Cloudinary account. Not yet run against the real account (`--storage-check` does a save/read/delete round trip). Signed URLs for the browser and upload validation beyond size/type are still open.

Build note (2026-11-03): on staging every PDF or ZIP read failed with HTTP 500 (export download, PDF receipt view) while images worked, which fits Cloudinary restricting PDF and ZIP delivery. The store now reads through Cloudinary's signed API download first, falls back to the delivery URL, and logs the upstream status code and the start of the reply on a failure. Not yet confirmed on staging: if it still fails, read the Render log for 'CloudinaryFileStore'. The Cloudinary setting 'PDF and ZIP files delivery' can also be enabled.
